# Jester status — start here (September 29, 2026)

Jester is the owner's Discord voice assistant. This page is for whoever picks it up next:
what it is, what works, what is still broken, and how to check your changes.

## What it is

- **Node app** (`src/`): joins the owner's voice room, decides what each utterance means, answers
  out loud, and drives agent sessions through **EBI**, the owner's Discord agent relay
  (<https://github.com/Pu11en/ebi-agent-chat-relay>). A Discord thread is one agent session.
- **Python speech worker** (`worker/speech.py`): Silero VAD, Parakeet speech-to-text on the GPU,
  and text-to-speech.
- **Brain:** Codex (`src/brain.mjs`, model "Luna") with the Claude CLI as a backup
  (`src/claude-brain.mjs`, `src/brain-fallback.mjs`). The owner's Codex quota is out until
  October 4, 2026, so Claude answers until then.
- **EBI API used:** see `EBI_INTERFACES.md` (mainly `GET /api/jester/sessions`).

## What works (verified live on September 29)

- Session questions are answered **without any model**, from EBI's snapshot: "what's open",
  "do you see podlox", "why is there no tag", "find meme explorer". It also names threads that
  other bots run.
- Actions by voice: "tell zoro to …", "start a session in <project> to …", "stop zoro",
  "close zoro".
- Coughs and "mm-hmm" do not stop Jester; real words, "Jester, stop" or about 1 s of sustained
  speech do. Jester never says "mm-hmm" itself.
- If Codex is out, Claude answers. Jester only says "Luna is out until October 4" when both
  brains are really down.

## Still broken or weak — what to fix

1. **Echo when the owner uses speakers.** There is no echo cancellation. On speakers Jester hears
   its own voice, transcribes it as the owner talking and cuts itself off. Evidence (room transcript,
   21:45 UTC): Jester said "Luna is out" and the next line, attributed to the owner, is
   "Munya is out." Headphones avoid it. A fix: while Jester speaks, drop owner segments whose words
   match what Jester is saying, or whose `stt_logprob` is low (turn_end events carry it).
2. **"Explain what's going on in <thread>" is shallow.** `src/session-reader.mjs` reads only the
   newest ~12 messages, and the answer is 1–2 sentences. The owner wants Jester to *ask the thread's
   own agent* a well-written, read-only question and relay its answer, using a private copy of that
   session so nothing is posted in the thread. Claude: `claude -p --resume <id> --fork-session
   --permission-mode plan`. Codex: `codex exec fork <id> --sandbox read-only`. This needs a new EBI
   endpoint that runs the fork and returns the answer.
3. **Speed:** 2–4 s from the end of the owner's speech to Jester's first word (target about 1.5 s).
4. **Untested with real models:** the new 9-frame speech gate has fake-model tests only
   (`worker/tests/test_speech_gate.py`). Run `worker/tests/test_speech.py` when the GPU is free.
5. **Small owner choices still open:** "stop it", "hold up" and "hush" are not stop phrases yet;
   a bare "No." counts as real words.

## How to check a change

```bash
npm test                      # all Node tests (267 pass on this commit)
node sim/run.mjs              # 19 offline conversation scenarios, all pass
bench/.venv/bin/python -m pytest -q worker/tests/test_speech_gate.py worker/tests/test_scaffold.py
```

On the owner's machine, Jester runs as the user service `jester-voice.service` from the `main`
checkout. Logs: `journalctl --user -u jester-voice.service` and `logs/turns.jsonl` (row types:
`turn` with `ownerText`, `barge_in`, `backchannel_ignored`, `brain_error`, `brainSwitched`,
`owner_intent`). Room transcripts are markdown files written by `src/transcript.mjs`.
