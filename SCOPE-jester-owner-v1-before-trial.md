# Jester owner V1: full scope before another voice trial

September 28, 2026. This is the owner-only product scope, based on [HANDOFF.md](HANDOFF.md), the Wayfinder decisions, current Jester/EBI code, the local service journals, and Drew's first real room transcripts. It replaces the assumption that passing component tests means Jester is ready to command real projects. **Do not ask Drew to try real session work again until the entry checks below pass.** Guest conversation and grants, automatic model fallback, and an overnight build schedule remain out of scope.

The foundation is real: the service joins Discord, transcribes, speaks through Luna and Kokoro, writes room transcripts, recognizes several exact commands, and has EBI receipt APIs. The complete natural voice-to-EBI path has not passed a live test; the first trial exposed failures before a task was handed off.

## What “usable as my commander” means

Drew says **Jester** to start an exchange, then speaks naturally. Jester hears the complete thought, including pauses and corrections; knows whether Drew is asking a question or assigning work; resolves the right current or past EBI session; and sends **one clean prompt** with the same effect as typing it in that thread. EBI agents do the file, browser, command and project work. Jester reports what it actually verified, answers later status questions from EBI evidence, and stays quiet unless addressed or explicitly asked to watch a result. It must work across many sessions and recover from a restart without sending a task twice.

## Why Zoro failed, specifically

- At about **14:42 CDT**, the room transcript captured Drew asking for help with his audit and correcting the name to Zoro. A replay of the final wording returns **no owner intent** from today's parser. It therefore went to generic Luna chat, which had no EBI facts; Jester asked what kind of audit it was.
- The live EBI snapshot **does contain Zoro**, in Drew's Audit, but reports `history` and no `current_task`. Even the exact supported phrase “Jester, what is Zoro doing?” would currently say little more than “Zoro is history.” EBI's recent-thread-messages endpoint does return messages; Jester's status answer does not read them.
- The EBI access journal contains **zero spoken-task and zero spawn POSTs** during the 13:55–14:43 CDT trial, despite many Jester session GETs. The recorded LinkedIn/Jobs creation request also returned no intent because it was spread across turns. These are observed routing misses, not proof that a real task was delivered.

## Behavior decisions already settled

- **Wake and silence:** `Jester` starts an exchange. Drew's genuine follow-ups need no repeated name for up to his chosen 60-second window; ambient or guest conversation closes it sooner. Direct tag instructions work only while Jester is engaged. It stays quiet by default about session changes.
- **Modes and people:** Only Drew controls Jester and EBI in V1. Guests may be transcribed and pause recording; guest conversation/control stays deferred. Just-listen blocks replies and EBI actions. An intentional leave disconnects.
- **Computer work:** Luna interprets speech; Jester code checks and routes; EBI sessions execute. One Codex/Luna brain path is used. If unavailable, Jester says so and keeps safe deterministic controls; it does not silently change to a paid model.
- **Action wording:** One faithful cleaned prompt is sent automatically when complete and unambiguous. Drew can request readback/revision. Clear owner tasks do not require a typed confirmation ritual.
- **Explicit empty sessions:** The observed request to open a thread before giving its task should create an empty thread when clearly requested. EBI's current spawn endpoint requires a prompt, so this needs a small separate EBI change; no invented seed task.

## Build order and proof before another live try

1. **Trace and replay the failures.** Add the private action trace, then replay the actual Zoro, LinkedIn, side-talk, leave, and “both” examples against fake EBI state. Every replay must state `answer`, `ask`, `act`, or `ignore` and the exact target/side-effect count. This makes future misses diagnosable.
2. **Repair hearing and conversation control.** Fix STT memory/recovery, Luna interruption race, side-talk disengagement, clear leave phrases, and just-listen restart behavior. Check 20 minutes of local two-speaker audio fixtures on the real GPU with normal concurrent EBI load, without repeated allocation errors. Save the real room interaction check for the final supervised trial.
3. **Make Zoro status useful with no side effects.** Build complete exact lookup, recent-work retrieval and an evidence-based answer for both “What is Zoro doing?” and natural “Help me with Zoro's audit.” Test history/idle/running/failed/unknown, aliases and >100 sessions. This is the first read-only commander milestone.
4. **Build natural draft → checked action.** Add typed intent proposals and multi-turn draft state, corrections, optional readback, exact project/tag/history resolution, and clear `send/create/stop/close/runtime` paths. Test zero sends for incomplete or ambiguous speech and exactly one for a complete request. Handle explicit empty-thread creation through a coordinated EBI API change.
5. **Make delivery and long-running status truthful.** Persist action IDs, reconcile receipts and first-turn state, restore after restart, enrich on-demand status, and verify requested dependencies/watches including contextual “both.” Test uncertain timeouts and replayed audio without duplicate work.
6. **Close replacement and quality gaps.** Verify transcript finalization, Discord post/privacy controls, mute display, allwork parse, resource cleanup, and end-of-speech-to-first-audio time under load. Re-run all automated checks and inspect the action trace for each scenario.
7. **Only then run a supervised owner trial.** Start with read-only Zoro status, then a deliberately disposable EBI thread and one harmless prompt, corrections and a follow-up, on-demand status, just-listen, leave, and restart. Compare the transcript, exact destination prompt, receipt, and spoken claims. Real project use begins only after that full path passes and Drew says the feel is right.

The work is larger than a voice bug fix. The earlier hour estimates are **not a readiness schedule**; size each checked change after the trace/replay reveals the remaining behavior. No overnight queue or guest features are part of this V1 scope.
